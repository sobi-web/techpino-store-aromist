# سند فنی «دیسکاوری ست آرومیست»

نسخه‌ی سند: ۲ — ۲۳ مهر ۱۴۰۵
وضعیت: **مرحله‌های ۱ تا ۳ پیاده‌سازی شد** (نسخه‌ی 0.3.0، ۲۳ مهر ۱۴۰۵): هسته، صفحه‌ی اختصاصی هر ست، صفحه‌ی ست‌ها، «ست خودت را بساز» و «ست‌های من». روی staging خام (کپی دست‌نخورده‌ی بک‌آپ ۲۲ مهر، PHP 8.1 + ionCube) تست شد: ۲۶۵ تست خودکار، خرید کامل از تسویه‌ی اختصاصی و بررسی ریسپانسیو. مرحله‌ی ۴ اختیاری است.

این سند همه‌ی تصمیم‌های گفتگو و نتیجه‌ی بررسی کد ووکامرس و افزونه‌های سایت را یک‌جا دارد. هر بخشی که با خواسته‌ی شما فرق دارد را علامت بزنید.

## ۲. تصمیم‌های گرفته‌شده

| موضوع | تصمیم |
|---|---|
| تعداد عطر | **۴** عطر متفاوت در هر ست (هم ست آماده، هم ست کاربر). |
| حجم | یک حجم برای کل ست (همه‌ی ویال‌ها یک‌اندازه). فهرست حجم‌های مجاز در تنظیمات (پیش‌فرض ۲، ۵ و ۱۰ میل). هر ست آماده می‌تواند فقط بعضی از آن‌ها را ارائه کند. مشتری حجم را انتخاب می‌کند. |
| قیمت | جمع قیمت ۴ عطر در همان حجم، منهای **یک تخفیف درصدی کلی** برای همه‌ی ست‌ها، به‌علاوه‌ی هزینه‌ی بسته‌بندی همان حجم، گرد شده. |
| قیمت هر عطر در یک حجم | اگر متغیری دقیقاً با همان حجم وجود دارد ← قیمت همان متغیر. وگرنه ← قیمت هر میلِ **کوچک‌ترین** متغیر × حجم. قیمت فعال (با حراج) ملاک است. |
| قیمت دستی | هر ست آماده می‌تواند به جای محاسبه‌ی خودکار، برای هر حجم قیمت ثابت داشته باشد. |
| عطرهای مجاز | فقط عطرهای متغیر منتشرشده‌ای که **موجودی حجمی** دارند. |
| موجودی | برداشت از **مخزن میلی‌لیتری هر ۴ عطر** (حجم + هدررفت هر عطر) و **یک عدد جعبه** از موجودی جعبه‌ها. |
| جعبه | جعبه‌ها در تنظیمات تعریف می‌شوند و هر حجم به یک جعبه وصل می‌شود (یا «بدون شمارش جعبه»). پیش‌فرض: یک جعبه برای همه‌ی حجم‌ها. |
| قالب صفحه | قالب Single Product المنتور با شرط «دسته‌ی دیسکاوری ست». افزونه هر ست آماده را خودکار در این دسته می‌گذارد. |
| گالری | زنده از تصویر شاخص ۴ عطر خوانده می‌شود (کپی نمی‌شود). |
| بخش‌های سفارشی سایت | سبد، تسویه، مینی‌کارت تک‌پینو و پنل کاربری بدون تغییر کار می‌کنند؛ محتوای ست از هوک‌های استاندارد (`woocommerce_get_item_data` و متای قابل‌نمایش آیتم سفارش) به آن‌ها می‌رسد. |
| حجم (۲۲ مهر) | همه‌ی ست‌ها **۴ عطر × ۱۰ میل**؛ انتخاب حجم حذف شد (موتور قیمت/موجودی حجم‌های دیگر را هم پشتیبانی می‌کند — فیلتر `ads_allowed_volumes`). |
| عطرهای مجاز (۲۳ مهر) | **فقط عطرهای دارای مخزن موجودی حجمی** (هم ست آماده، هم ست اختصاصی). |
| تخفیف (۲۳ مهر) | **دو درصد جدا**: ست‌های آماده و ست‌های اختصاصی (ست آماده‌ای که «شخصی» شود، ست اختصاصی حساب می‌شود). |
| عطرهای سازنده (۲۳ مهر) | **فقط عطرهایی که مدیر تیک می‌زند** («عطرهای ست اختصاصی» یا تیک در صفحه‌ی عطر). |
| ست‌های من (۲۳ مهر) | **فقط ست‌های ذخیره‌شده در سازنده** (ذخیره نیاز به ورود دارد؛ مهمان می‌تواند بسازد و بخرد). ست‌های خریده‌شده در «سفارش‌ها» دیده می‌شوند. |
| صفحه‌ی ست (۲۳ مهر) | طراحی اختصاصی افزونه؛ **نظرات با امتیاز**؛ هر عطر با همه‌ی اطلاعات صفحه‌ی محصول (ویژگی‌ها، نام انگلیسی، گروه بویایی، نت‌ها)؛ دکمه‌ی «این ست را شخصی کن». |
| نمایش در فروشگاه (۲۳ مهر) | ست‌ها **فقط در صفحه‌ی دیسکاوری ست‌ها** (و جستجو)؛ نه در فروشگاه و دسته‌های عطر (قابل تغییر در تنظیمات). |
| گالری (۲۳ مهر) | گالری انتخاب‌شده در پیشخوان؛ اگر خالی باشد تصویر شاخص ۴ عطر. |

## ۳. یافته‌های بررسی کد

## ۴. مدل داده

**محصول ست** (نوع محصول `discovery_set`، کلاس `WC_Product_Discovery_Set`، موجودی ندارد):

| متا | معنی |
|---|---|
| `_ads_components` | آرایه‌ی ۴ شناسه‌ی عطر (محصول مادر) به ترتیب نمایش |
| `_ads_component` (چند ردیف) | همان شناسه‌ها، برای جستجوی «این عطر در کدام ست‌هاست» |
| `_ads_volumes` | حجم‌هایی که این ست ارائه می‌کند |
| `_ads_default_volume` | حجم پیش‌فرض (قیمت و مرتب‌سازی فروشگاه بر اساس این حجم است) |
| `_ads_price_mode` | `auto` یا `fixed` |
| `_ads_fixed_prices` | قیمت ثابت هر حجم (حالت `fixed`) |
| `_ads_is_custom` | `yes` فقط برای محصول مخفی «ست سفارشی» (ست ساخت کاربر) |
| `_regular_price`، `_sale_price`، `_price`، `_stock_status` | خودکار همگام می‌شوند (قیمت حجم پیش‌فرض و «موجود اگر حداقل یک حجم قابل فروش باشد») تا فهرست فروشگاه، فیلترهای قیمت و ویجت‌های المنتور/جت‌انجین درست کار کنند. |

**جعبه:** محصول ساده‌ی خصوصی (`_ads_box = yes`) که موجودی ووکامرس دارد. کم/زیاد شدن آن اتمی است و ایمیل «موجودی کم» ووکامرس برایش ارسال می‌شود.

**عطر:** `_ads_in_builder = yes` ← در «ساخت دیسکاوری ست» ارائه می‌شود.

**کاربر:** `_ads_saved_sets` = فهرست «ست‌های من»: `{ id, name, c: [۴ شناسه‌ی عطر], created, updated }` (آخرین تغییر اول). فقط شناسه‌ها؛ قیمت و موجودی همیشه لحظه‌ای.

**تنظیمات (`ads_settings`):** `discount` (ست آماده)، `custom_discount` (ست اختصاصی؛ خالی = همان)، `max_saved_sets`، `volumes` (یک ردیف ۱۰ میل: هزینه‌ی بسته‌بندی و جعبه)، `round_to`، `archive_page_id`، `builder_page_id`، `own_template`، `show_in_shop`، `custom_product_id`، `category_id`.

**آیتم سبد:** `ads = { v: حجم, c: [۴ شناسه‌ی عطر] }`. قیمت در هر بار محاسبه‌ی سبد از قیمت‌های لحظه‌ای ساخته می‌شود.

**آیتم سفارش:**

| متا | معنی |
|---|---|
| `حجم هر عطر` (قابل نمایش) | مثلاً «۵ میل» |
| `عطرها` (قابل نمایش) | نام ۴ عطر با «،» |
| `_ads_set` | عکس لحظه‌ی خرید: حجم، عطرها (شناسه، نام، میل هر واحد با هدررفت)، جعبه، فهرست برداشت‌ها `draws = [{p: شناسه، a: مقدار برای یک ست}]` |
| `_ads_reduced` | مقدار برداشت‌شده از هر محصول برای کل آیتم (برای برگشت دقیق) |
| `_ads_refunded` | تعداد ست‌های مرجوعی که به انبار برگشته‌اند |

## ۵. رفتار موجودی

| اتفاق | اثر |
|---|---|
| افزودن به سبد / تغییر تعداد | برای هر عطر: (میل همه‌ی آیتم‌های سبد از آن عطر، چه حجم معمولی چه ست) ≤ مخزن − رزرو دیگران. برای جعبه هم همین‌طور. وگرنه پیام فارسی و رد. |
| ورود به درگاه | سهم ست‌ها در جدول رزرو ووکامرس (همان مدت «نگه‌داشتن موجودی») ثبت می‌شود. |
| پرداخت / «در حال انجام» / «در انتظار بررسی» | `تعداد × (حجم + هدررفت)` از هر مخزن و `تعداد` از جعبه کم می‌شود؛ تاریخچه‌ی موجودی حجمی و یادداشت سفارش ثبت می‌شود. |
| لغو / ناموفق / برگشت به «در انتظار پرداخت» | دقیقاً همان مقدار برمی‌گردد. |
| مرجوعی با «بازگرداندن به انبار» | سهم همان تعداد مرجوعی برمی‌گردد (هرگز بیشتر از برداشت). |
| ویرایش تعداد / حذف آیتم در پیشخوان | اختلاف کم/زیاد می‌شود. |
| تمام شدن یکی از عطرها یا جعبه | ست‌های آماده‌ی مربوط خودکار «ناموجود» یا حجم‌های ناممکن غیرفعال می‌شوند. |
| حذف / پیش‌نویس / غیرفعال شدن موجودی حجمی یک عطر | ست‌های شامل آن ناموجود می‌شوند، در پیشخوان هشدار داده می‌شود، و آیتم‌های سبد شامل آن با پیام حذف می‌شوند. |

## ۶. مرحله‌ها

### مرحله‌ی ۱ — هسته (0.1.2)
- نوع محصول «دیسکاوری ست» و تب «محتوای ست» (۴ جای عطر با جستجو، حجم‌ها، حجم پیش‌فرض، حالت قیمت، پیش‌نمایش قیمت و موجودی هر حجم).
- صفحه‌ی تنظیمات: حجم‌ها (هزینه‌ی بسته‌بندی، جعبه)، تخفیف کلی، گرد کردن، جعبه‌ها و موجودی‌شان، محصول «ست سفارشی».
- قیمت‌گذاری، همگام‌سازی قیمت و وضعیت موجودی، گالری خودکار، دسته‌ی خودکار.
- سبد خرید (هر دو نوع ست، از جمله API افزودن ست سفارشی)، آیتم سفارش، کسر/برگشت/رزرو/مرجوعی/ویرایش.
- فرم ساده‌ی افزودن به سبد در صفحه‌ی محصول (انتخاب حجم، قیمت زنده).
- جعبه‌ی «برداشت از انبار» زیر آیتم در صفحه‌ی سفارش پیشخوان.
- تست خودکار.

### مرحله‌ی ۲ — صفحه‌ها و تجربه‌ی خرید (0.3.0) ✓
- صفحه‌ی اختصاصی هر ست (به‌جای ویجت‌های المنتور): گالری لمسی، «داخل این ست»، تب هر عطر با اطلاعات کامل صفحه‌ی محصول، نظرات، ست‌های دیگر، نوار چسبان موبایل.
- افزودن AJAX با فرگمنت‌های ووکامرس و انیمیشن پرواز ویال‌ها به آیکن سبد؛ مینی‌کارت تک‌پینو خودش باز می‌شود.
- «این ست را شخصی کن» ← سازنده با عطرهای همان ست.
- صفحه‌ی «دیسکاوری ست‌ها» با آدرس‌های `/discovery-sets/نام-ست/`.

### مرحله‌ی ۳ — «ست خودت را بساز» و «ست‌های من» (0.3.0) ✓
- سازنده: عطرهای انتخابی مدیر، جستجو و فیلتر، پنجره‌ی جزئیات، جعبه‌ی ۴ خانه با قیمت زنده (تخفیف ست اختصاصی)، کشوی موبایل.
- ذخیره / ویرایش / حذف ست برای کاربر واردشده؛ تب «ست‌های من» در پنل کاربری تک‌پینو با «خرید» و قیمت لحظه‌ای.
- صفحه‌ی «عطرهای ست اختصاصی» در پیشخوان و تیک در صفحه‌ی هر عطر.

### اصلاحات طراحی (0.3.3، ۲۳ مهر ۱۴۰۵) ✓
- صفحه‌ی ست: گالری روی پس‌زمینه‌ی جدا با سایه؛ تصویر کامل (`object-fit: contain`)؛ رفع پرش تک‌اسلایدی فلش‌ها و تصاویر کوچک (حذف `scroll-snap-stop`)؛ حذف سه نکته‌ی «۴ ویال…»؛ عنوان «عطرهای ۱۰ میل داخل این ست».
- تب هر عطر و پنجره‌ی «جزئیات» سازنده: تصاویر گالری عطر، حداکثر ۲ مقدار برای هر ویژگی، لینک گروه بویایی / نت‌ها / مقدارهای دارای آرشیو به صفحه‌ی خودشان، ۵ نت در هر سطح و «نمایش بیشتر».
- سازنده: فهرست‌های انتخابی جنسیت، فصل، گروه بویایی، حال و هوا و شخصیت (به‌جای دکمه‌های «برای» و «گروه بویایی»)؛ جستجو حفظ شد.

### آرشیو با دسته‌ها و نام ست (0.3.4، ۳ آبان ۱۴۰۵) ✓
- دسته‌های ووکامرس: «دیسکاوری ست» ← «دیسکاوری ست مردانه» / «دیسکاوری ست زنانه». بالای صفحه‌ها را مدیر در المنتور طراحی می‌کند؛ افزونه فقط محتوا را با شورت‌کد می‌دهد.
- `[aromist_discovery_sets]` با کوئری ووکامرس: در قالب آرشیو هر دسته، ست‌های همان دسته (با زیردسته‌ها). ست‌ها از فهرست فروشگاه پنهان‌اند (`catalog visibility`)، پس ویجت «محصولات آرشیو» المنتور آن‌ها را نشان نمی‌دهد و شورت‌کد خودش کوئری می‌زند. گزینه‌ها: `category`، `columns`، `limit`، `builder_card`، `hero` (پیش‌فرض بدون hero). `[aromist_set_builder hero="no"]`.
- لینک «دیسکاوری ست‌ها» → آرشیو دسته (تنظیم `archive_link`: category | page). مسیر صفحه‌ی ست با زیردسته؛ «ست‌های دیگر» اول از همان زیردسته.
- کارت‌ها با container query: زیر ۵۶۰px جعبه‌شان افقی؛ کارت عطرهای سازنده زیر ۵۲۰px ستون کاتالوگ افقی. داخل ویجت کد کوتاه المنتور، حاشیه‌ی کناری و حداکثر عرض `.ads-wrap` حذف می‌شود.
- نام ست اختصاصی: `ads['n']` روی آیتم سبد (فقط وقتی نام داده شده)، روی شیء محصول آیتم (`set_name`) هنگام افزودن، بازیابی از سشن و هر محاسبه‌ی مجموع؛ نام ردیف سفارش و `_ads_set['name']`. AJAX `ads_add_to_cart` پارامتر `name` می‌گیرد؛ فیلد نام در سازنده برای همه.

### مرحله‌ی ۴ (اختیاری)

## ۷. محدودیت‌ها
- سبد و تسویه‌ی بلوکی ووکامرس (Store API) پشتیبانی نمی‌شوند.
- روی SQLite (سایت تست محلی) کوئری قفل‌دار رزرو اجرا نمی‌شود؛ بخش رزرو باید روی staging با MySQL تست شود (مثل افزونه‌ی موجودی حجمی).
- قبل از غیرفعال کردن افزونه، ست‌ها را پیش‌نویس کنید؛ وگرنه ووکامرس آن‌ها را محصول ساده با قیمت ذخیره‌شده می‌بیند.
